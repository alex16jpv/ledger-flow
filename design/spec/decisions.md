# Decision log

Every decision that shaped the UI, newest first. This is the one file in the specification that keeps
the tracker's codes (`F-nn`, `P-nn`, `W-nn`, `D-nn`): it is the audit trail, and it is what ties a
screen back to the row that asked for it in `PROGRESO.md`. The screens themselves are named after what
they are, never after a ticket.

| 2026-09-11 | **P-46 · the install card insists by platform, and says only what is true there** (owner's decision). It never appears on a **desktop**: the browser puts its own install button in the address bar and Settings › About carries the row, so a card on top of that is insistence without a reason. On **Android** it keeps the seven-day snooze and gives up on the third dismissal. On **iOS** it snoozes three days and **never gives up**, because Safari is the only place that really deletes the data and the only one where no install prompt of any kind exists — a page cannot ask, the way it can ask for a location. The copy leads with what installing is actually for (the app is fully usable from the tab, so the reason is the offline copy) and drops the word "phone", which was wrong on a tablet and on a desktop; the sentence about the browser deleting the data is kept **only where the browser has not granted durable storage** — every iPhone, and any Android that was told no — because where it was granted the warning would be false. And the install steps now follow the platform instead of `maxTouchPoints`, which handed a touch-screen Windows laptop the iPhone's instructions. |
